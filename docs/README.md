# docs

User-facing documentation, one file per topic. `PLAN.md` at the repository
root is the design document these pages summarize for a reader who wants to
use the tool rather than build it; `CHANGELOG.md` says which slice landed
which piece.

- [usage.md](usage.md) — every CLI flag, with one real, executed example
  each.
- [reports.md](reports.md) — the three artifacts one run can produce: the
  versioned JSON, the Markdown issue draft, and the emitted regression test.
- [corpus.md](corpus.md) — what `cases/` is for and how the two file shapes
  in it relate; [`cases/README.md`](../cases/README.md) is the detailed
  reference for adding a case.
- [validation.md](validation.md) — compile-check run against public,
  CPU-runnable models, regenerated by [`validation/run.py`](../validation/run.py).
- [action.md](action.md) — using compile-check as a GitHub Action: inputs,
  outputs, baseline semantics, and what the self-test workflow does and does
  not cover.
- [cross-arch.md](cross-arch.md) — the copy-paste runbook for running
  compile-check on a second machine (an x86 CPU box, a CUDA box) and diffing
  its results against the committed aarch64 run, and what cross-architecture
  parity means.
- [release.md](release.md) — the maintainer's runbook for the four steps M4
  prepares and does not take: the tag, the PyPI upload, the public flip, and
  the Marketplace listing, with what each one makes visible and which of them
  cannot be undone.
